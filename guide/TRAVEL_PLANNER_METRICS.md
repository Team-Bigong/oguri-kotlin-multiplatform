# 여행 기능 지표

통합 명세 14.2의 지표를 위한 서버 확정 사실 수집이다. 현재 구현은 생성·참여·첫 날짜 배정 저장·참여 이후 편집의 기초 집계까지다. 세션을 구분한 준비 기간 재사용이나 90일 다음 여행 재사용률을 구현 완료한 상태는 아니다.

## 저장 경계

- V42의 `travel_usage_cohorts`는 사용자–여행의 첫 관측 시작을 기록한다. 신규 생성은 `CREATED`, 명시적인 첫 참여는 `JOINED`이며, 링크 발급·미리보기·공유는 참여가 아니다. 재시도·재참여로 시작 시점을 바꾸지 않는다.
- 수집 이전 여행은 실제 생성·참여 시점을 추측하지 않고 `EXISTING`으로 구분한다. 이 행의 `days_until_start`는 미상이며 신규 시작의 분모에 포함하지 않는다. 과거 기록을 소급 생성하지 않는다.
- `days_until_start`는 시작 당시 여행 시간대의 날짜와 출발일의 차이다. `initial_end_at`은 당시 마지막 여행 날짜가 끝나는 시각이다. 여행 기간 변경·나가기·제외·삭제로 이 기준을 다시 쓰거나 관찰 행을 빼지 않는다.
- `travel_usage_edits`는 서버가 수락한 편집을 여행 수정 번호당 한 번 기록한다. 생성·참여·편집과 같은 DB 트랜잭션이므로 실패·충돌·롤백은 성공으로 남지 않는다. 수정 요청 재전송도 중복 기록하지 않는다.
- `has_dated_visit`는 저장 결과에 날짜가 배정된 방문이 하나 이상 있다는 뜻이다. 시각·메모·재정렬 여부는 활성화 조건이 아니다. 신규 생성 여행에서 이 조건을 처음 만족하는 저장을 첫 활성화로 집계한다.
- `after_participation`은 다른 멤버가 참여한 뒤 저장한 편집이다. 링크 발급만으로 참이 되지 않으며, 이후 멤버가 나가도 과거 참여 사실은 유지한다. 이를 협업의 인과 효과나 품질로 해석하지 않는다.

기록은 앱 소유 서버 DB에만 저장하며 외부 분석 서비스로 전송하지 않는다. 제목·도시명·방문 이름·위치·메모·시각·검색어·외부 장소 정보·초대값·개인 연차·요청 본문·기기 토큰은 저장하지 않는다. 유형은 제한된 값만 허용하고 임의 속성 필드를 두지 않는다. 여행 삭제 시 여행 참조, 계정 삭제 시 회원 참조를 비우되 임의의 관찰 식별자와 집계 사실을 남긴다. 일반 나가기는 회원 참조를 유지하고, 계정 삭제 시에만 회원 참조를 비운다. 두 경우 모두 관찰 분모를 유지한다.

## 기초 집계

읽기 전용 DB 계정으로 저장소 루트에서 실행한다. 접속 주소는 운영 환경의 관리 절차에 따라 별도로 설정한다.

```sh
PGOPTIONS='-c default_transaction_read_only=on' psql "$TRAVEL_METRICS_DATABASE_URL" \
  -v ON_ERROR_STOP=1 --single-transaction -f scripts/report_travel_usage.sql
```

보고서는 식별자를 반환하지 않고 `DIRECT`/`RECOMMENDATION`별 생성·활성화·참여 후 편집·참여 수를 반환한다. 도시가 미정인 기간 추천도 `RECOMMENDATION`에 포함한다. 시작 당시 출발까지 8일 이상이고 시작 후 7일이 지난 집단, 아직 관찰 중인 집단, 임박·여행 중·과거 여행·시작 미상 집단을 구분한다. 임박 여부를 현재 수정된 날짜로 다시 분류하지 않는다.

집계 기간·목표·표본은 실험 전에 정해야 한다. 이 기본 보고서는 전체 수집 기간의 기초 수이며, 대조군 비교나 실제 리텐션 상승률을 제공하지 않는다. 새 마이그레이션만으로 수집 이전 여행의 시작·활성화 기록을 복구할 수 없다.

## 남은 수집과 검증

- 추천 진입 노출·클릭·로그인 복귀의 진입원과 회원 여부, 실제 화면 표시를 분리해 수집한다.
- 세션을 구분하고 날짜·핀·변경 확인·길찾기·편집의 목적 있는 행동을 연결한다. 앱 실행·푸시 클릭만으로 재사용을 세지 않는다. 시작 후 24시간부터 7일 이내의 다른 세션 재사용과 단순 표시 재방문을 분리한다.
- 사용자–여행 단위와 사용자 전체 단위를 따로 집계하고, 첫 종료 여행 이후 90일 관찰 중·관찰 완료를 구분한다. 추천 탐색과 새 생성·참여도 구분한다.
- 저장 실패·충돌 복구·알림 해제는 확정 성공과 분리한다. 발송 접수·기기 표시는 같은 이벤트로 취급하지 않는다. 실제 사용자 과업·민원·리플레이 차단 검증은 별도다.

기초 사실만으로 위 미구현 지표의 성공률을 계산하거나 미수집 행동을 실패로 확정하지 않는다.
