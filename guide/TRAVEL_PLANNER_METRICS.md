# 여행 기능 지표

통합 명세 14.2의 지표를 위한 서버 확정 사실 수집이다. 현재 구현은 생성·참여·첫 날짜 배정 저장·참여 이후 편집과 세션을 구분한 준비 기간 재사용 집계다. 추천 진입 노출/클릭, 변경 확인 후 후속 행동, 실패/알림 해제, 90일 다음 여행 재사용률과 실제 사용자 검증은 남아 있다.

## 저장 경계

- V42의 `travel_usage_cohorts`는 사용자–여행의 첫 관측 시작을 기록한다. 신규 생성은 `CREATED`, 명시적인 첫 참여는 `JOINED`이며, 링크 발급·미리보기·공유는 참여가 아니다. 재시도·재참여로 시작 시점을 바꾸지 않는다.
- 수집 이전 여행은 실제 생성·참여 시점을 추측하지 않고 `EXISTING`으로 구분한다. 이 행의 `days_until_start`는 미상이며 신규 시작의 분모에 포함하지 않는다. 과거 기록을 소급 생성하지 않는다.
- `days_until_start`는 시작 당시 여행 시간대의 날짜와 출발일의 차이다. `initial_end_at`은 당시 마지막 여행 날짜가 끝나는 시각이다. 여행 기간 변경·나가기·제외·삭제로 이 기준을 다시 쓰거나 관찰 행을 빼지 않는다.
- `travel_usage_edits`는 서버가 수락한 편집을 여행 수정 번호당 한 번 기록한다. 생성·참여·편집과 같은 DB 트랜잭션이므로 실패·충돌·롤백은 성공으로 남지 않는다. 수정 요청 재전송도 중복 기록하지 않는다.
- `has_dated_visit`는 저장 결과에 날짜가 배정된 방문이 하나 이상 있다는 뜻이다. 시각·메모·재정렬 여부는 활성화 조건이 아니다. 신규 생성 여행에서 이 조건을 처음 만족하는 저장을 첫 활성화로 집계한다.
- `after_participation`은 다른 멤버가 참여한 뒤 저장한 편집이다. 링크 발급만으로 참이 되지 않으며, 이후 멤버가 나가도 과거 참여 사실은 유지한다. 이를 협업의 인과 효과나 품질로 해석하지 않는다.

기록은 앱 소유 서버 DB에만 저장하며 외부 분석 서비스로 전송하지 않는다. 제목·도시명·방문 이름·위치·메모·방문 시각·검색어·외부 장소 정보·초대값·개인 연차·요청 본문·기기 토큰은 저장하지 않는다. 유형은 제한된 값만 허용하고 임의 속성 필드를 두지 않는다. 여행 삭제 시 여행 참조, 계정 삭제 시 회원 참조를 비우되 임의의 관찰 식별자와 집계 사실을 남긴다. 일반 나가기는 회원 참조를 유지하고, 계정 삭제 시에만 회원 참조를 비운다. 두 경우 모두 관찰 분모를 유지한다.

## 기초 집계

읽기 전용 DB 계정으로 저장소 루트에서 실행한다. 접속 주소는 운영 환경의 관리 절차에 따라 별도로 설정한다.

```sh
PGOPTIONS='-c default_transaction_read_only=on' psql "$TRAVEL_METRICS_DATABASE_URL" \
  -v ON_ERROR_STOP=1 --single-transaction -f scripts/report_travel_usage.sql
```

보고서는 식별자를 반환하지 않고 `DIRECT`/`RECOMMENDATION`별 생성·활성화·참여 후 편집·참여 수를 반환한다. 도시가 미정인 기간 추천도 `RECOMMENDATION`에 포함한다. 시작 당시 출발까지 8일 이상이고 시작 후 7일이 지난 집단, 아직 관찰 중인 집단, 임박·여행 중·과거 여행·시작 미상 집단을 구분한다. 임박 여부를 현재 수정된 날짜로 다시 분류하지 않는다.

집계 기간·목표·표본은 실험 전에 정해야 한다. 이 기본 보고서는 전체 수집 기간의 기초 수이며, 대조군 비교나 실제 리텐션 상승률을 제공하지 않는다. 새 마이그레이션만으로 수집 이전 여행의 시작·활성화 기록을 복구할 수 없다.

## 세션과 준비 기간 재사용

V43은 최초 생성/참여와 확정 편집에 선택적인 세션 식별자를 추가한다. 이전 앱은 기존 API를 그대로 사용하며 세션은 미상으로 남는다. 이후의 행동으로 첫 세션을 추측해 채우지 않는다. 새 모바일 앱은 생성·참여·편집과 회원 전용 `POST /api/v1/trips/{tripId}/activity`에 `X-Travel-Session` 헤더를 붙인다. 서버는 현재 접근을 확인하고 종류를 제한하며 같은 사용자–여행·세션·행동을 한 번만 기록한다. 행동 시간은 서버 시각을 사용한다.

- 세션은 프로세스 시작 또는 마지막 화면 표시/사용자 행동 이후 30분 이상 공백, 계정 전환/다시 로그인 때 바뀐다. 자동 토큰 갱신은 같은 세션이다. 식별자는 무작위이며 토큰·회원 식별자·시간값을 포함하지 않는다.
- 계획이 실제 표시되어 활성화된 화면은 `PLAN_DISPLAYED`다. 시작/푸시 열기·서버의 단순 계획 조회·5초 자동 갱신·홈 이어보기 조회만으로 이 이벤트나 목적 행동을 만들지 않는다.
- 사용자가 날짜를 선택하거나 전체 날짜 보기를 실제 열거나 핀을 선택하거나 최근 변경을 표시하거나 외부 길찾기 열기에 성공하면 해당 행동을 기록한다. 자동 날짜 복원·알림의 날짜 이동은 사용자 날짜 선택으로 기록하지 않는다. 길찾기는 OS 열기 호출 성공이며, 외부 앱이 최종 경로를 표시했다는 의미는 아니다.
- 기록은 온라인으로 확인한 현재 계획에서만 시도한다. 오프라인 행동을 별도 저장/재전송하지 않는다. 기록 오류는 여행 상태·초안·접근 권한 처리를 바꾸지 않는다. 성공한 같은 세션의 같은 행동은 모바일에서도 다시 요청하지 않는다.
- 세션별 행동은 최초 시각만 기록하므로 조작 빈도·체류시간·같은 세션의 상세 행동 순서를 나타내지 않는다.

```sh
PGOPTIONS='-c default_transaction_read_only=on' psql "$TRAVEL_METRICS_DATABASE_URL" \
  -v ON_ERROR_STOP=1 --single-transaction -f scripts/report_travel_preparation_reuse.sql
```

시작 당시 출발까지 8일 이상이고 시작 후 7일이 지난 집단을 대상으로, 시작 후 **24시간부터 7일 이내**에 **첫 세션과 다른 세션**에서 목적 행동 또는 실제 편집 저장이 있었는지 본다. 표시만 된 재방문은 별도 열이며 목적 재사용 수에 합하지 않는다. 아직 7일이 안 된 집단은 관찰 중으로 반환한다.

전체 관찰 분모와 시작 세션이 알려진 분모를 나누어 반환한다. 시작 세션 미상은 재사용 실패로 확정하지 않는다. 사용자–여행 수와 계정별 고유 사용자 수는 별도 열이다. 계정 삭제 후 여러 관찰 행이 같은 사람인지 추측하지 않고, 계정 참조가 없는 관찰 수를 별도로 표시한다. `ALL` 행은 출처를 합친 전체 집계이며 계정별 사용자를 다시 중복 제거한다. 출처별 사용자 수를 더해 전체 사용자 수로 쓰지 않는다. 오프라인·통신 실패로 행동이 수집되지 않을 수 있으므로 보고서는 관측된 서버 기록의 집계이며 과업 완료율이나 실제 리텐션 효과를 증명하지 않는다.

## 남은 수집과 검증

- 추천 진입 노출·클릭·로그인 복귀의 진입원과 회원 여부, 실제 화면 표시를 분리해 수집한다.
- 변경 확인 이후의 후속 행동과 실제 사용자 과업을 추가로 검증한다. 현재의 세션별 최초 행동 시각만으로 모든 후속 행동 순서를 복원하지 않는다.
- 사용자–여행 단위와 사용자 전체 단위를 따로 집계하고, 첫 종료 여행 이후 90일 관찰 중·관찰 완료를 구분한다. 추천 탐색과 새 생성·참여도 구분한다.
- 저장 실패·충돌 복구·알림 해제는 확정 성공과 분리한다. 발송 접수·기기 표시는 같은 이벤트로 취급하지 않는다. 실제 사용자 과업·민원·리플레이 차단 검증은 별도다.

기초 사실만으로 위 미구현 지표의 성공률을 계산하거나 미수집 행동을 실패로 확정하지 않는다.
