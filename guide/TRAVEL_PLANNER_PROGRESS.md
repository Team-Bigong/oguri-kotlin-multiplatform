# 여행 플래너 구현 진행 기록

기준: 2026-11-13, `9eef5c4` 이후 이어서 작업. 이 기록은 이번 변경의 범위와 검증 결과이며, 공개 MVP 전체의 완료를 의미하지 않는다.

## 이번에 연결한 흐름 · P6

- 여행 화면의 `더보기`에서 멤버·여행 관리 화면을 열고, 개인 구역의 `내 알림`을 선택한다.
- 현재 본인 예약을 조회하고 날짜·현지 시각·수신 시간대를 입력해 출발 전 1회 알림을 예약하거나 해제한다. 기본 상태는 꺼짐이며, 예약을 직접 누를 때만 OS 권한을 요청한다.
- 미래 시각과 여행 시간대 기준 출발일 시작 전인지 검사한다. 존재하지 않는 서머타임 시각은 입력 단계에서 막는다. 서버가 시간대 중복 시각과 여행 구조·권한을 최종 검증한다.
- 예약 상태·권한 거절·통신 실패를 표시한다. 기간 변경으로 취소된 예약은 설정을 다시 조회하면 꺼짐으로 표시된다. 자동 재예약은 하지 않는다.
- 앱의 계정 세션·푸시 토큰 변경과 포그라운드 복귀에 기기 연결을 동기화한다. 로그아웃·계정 변경 시 이전 연결을 해제하며, 해제 요청 실패 기록은 다음 동기화에서 재시도한다.
- 알림을 누르면 서버에서 예약의 최신 상태와 현재 계정의 접근 권한을 확인한 뒤 여행을 연다. 로그인 중에는 진입 의도를 유지하고, 통신 실패는 재시도할 수 있다. 유효하지 않은 알림은 여행을 열지 않는다.
- 인증 갱신 재시도에서 같은 예약 요청 ID를 유지하고, 이전 계정의 푸시 토큰을 정리한 뒤 새 토큰을 얻도록 순서를 정리했다.
- 새 문구는 영어·한국어·일본어·중국어에 반영했다.

## 실행 검증

- `:composeApp:compileDebugKotlinAndroid`: 로컬 Firebase 설정을 포함해 통과.
- `:composeApp:compileKotlinIosSimulatorArm64`: 통과. Swift 호스트 앱 전체 빌드와 실제 APNs 전달을 확인한 결과는 아니다.
- `:composeApp:testDebugUnitTest`: 공통 테스트 12개 통과. 새 알림 테스트 5개는 수신 시간대 변환, 여행 시간대의 출발일 경계, 과거·현재 시각, 잘못된 입력, 서머타임 누락 시각을 검증한다.
- 변경한 Kotlin 파일만 대상으로 스타일 포맷·검사를 수행한다. 저장소 전체 검사는 생성된 네트워크 설정 소스와 관련한 기존 Gradle 태스크 의존성 문제를 별도로 해결해야 한다.
- 로컬 Firebase 파일은 각 `composeApp/src/debug`, `composeApp/src/release` 폴더에서 `google-services.json`이라는 이름을 사용한다. 두 파일 모두 Git 제외 대상이다.

## 최근 변경 상세 보완 · AC12

- V40에서 방문 식별자만 변경 기록에 추가한다. 삭제·이동 뒤에도 같은 방문을 구별하며, 장소 이름이나 메모 본문을 변경 이력으로 복제하지 않는다.
- 최근 변경 조회 시 현재 방문과 조인해 변경 시각, 현재 직접 입력 이름, 현재 배정 날짜를 응답한다. Google 장소 상세는 이력에 저장하지 않는다.
- 변경 항목은 최신순으로 표시하고, 이동한 방문은 현재 날짜로 연결한다. 삭제된 방문은 현재 삭제 상태를 안내하며 오래된 날짜로 이동시키지 않는다. 기간 단축 뒤 날짜 없음으로 옮겨진 방문도 이동할 수 있다.
- 현재 여행 기간·시간대를 함께 내려 주어 관리 화면을 연 뒤 기간이 바뀌어도 이전 날짜 범위를 사용하지 않는다. 이전 서버의 응답은 기존 일차 기반으로 호환한다.
- 모바일 테스트 5개로 이동·미배정·삭제·기간 단축·이전 응답의 이동 대상을 검증한다. 서버 테스트 3개로 추가·이동·삭제의 방문 식별자 기록을 검증한다.
- 검증: 모바일 공통 테스트 총 17개·여행 변경 서버 테스트 3개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사가 통과했다.
- 후속 임시 PostgreSQL 통합 검증에서 V40 업그레이드와 실제 최근 변경 SQL 조회가 통과했다.
- 초기 전체 서버 검사에서 `CalendarServiceTest`의 2026년 6월 고정 날짜 사례가 과거 날짜 필터로 실패했다. 후속 수정에서 테스트 연도를 현재 연도의 다음 해로 바꾸어 테스트 목적을 유지했고, 전체 서버 테스트 15개가 통과했다.


## 회원 전용 여행 일정 정책

- 사용자 정책 변경에 따라 비회원에게는 여행 목록·생성·편집·관리 대신 로그인 안내만 표시한다. 게이트 뒤에서만 해당 ViewModel과 입력 화면을 만든다.
- 로그인·가입 후에는 원래 진입 경로와 추천 도시·기간으로 복귀한다. 로그인 취소 시 일정 입력을 제공하지 않는다.
- 도시 검색·도시 시간대 API도 인증 대상에 추가하고 실제 회원 존재를 확인한다. 기존 여행 조회·쓰기·초대 참여의 회원 검증은 유지한다.
- 제한된 초대 안내, 기존 추천 탐색, 로그아웃 후 기기 연결 해제 API는 기존 목적대로 사용할 수 있다.
- 검증: 모바일 공통 테스트 17개, 여행 서버 테스트 7개(인증 정책·탈퇴 회원 차단 포함), Android·iOS Kotlin 컴파일 및 변경 파일 스타일 검사 통과.


## 여행 생성 재실행 복구 · AC16

- 회원의 이전 생성 요청을 로컬 저장소에서 확인하기 전에는 새 여행 생성을 막는다. 복구 읽기가 실패하면 새 요청으로 진행하지 않고 복구 확인을 재시도한다.
- 응답을 확인하지 못한 생성 요청이 남아 있으면 도시·여행 기간·시간대·제목·추천 출처를 복원한다. 사용자는 같은 요청 ID로 재시도한다.
- 복구 대기 중 생성, 복구 저장소 읽기 실패, 통신 결과 불명확 후 재시도, 생성 중복 탭을 ViewModel 테스트 4개로 검증한다.
- 검증: 모바일 공통 테스트 총 21개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 공동 편집 중 편집 상태 보호 · AC11·14·16

- 다른 멤버가 기간·시간대를 바꾸면 열린 방문 초안은 그대로 보존하고 최신 일정 확인을 요구한다. 사용자가 확인한 뒤 새 구조 버전을 적용하며 범위 밖 일차는 날짜 없음으로 옮긴다.
- 기간 단축으로 존재하지 않게 된 일차도 편집창·최근 변경에서 안전하게 표시한다. 유효하지 않은 일차로 날짜 계산을 하거나 날짜 문구의 필수 인자를 누락하지 않는다.
- 다른 멤버가 편집 중인 방문을 삭제하면 선택·지도 초점을 정리하고 삭제 상태를 표시하되, 사용자가 입력한 내용은 버리지 않는다.
- 독립적인 방문 필드 수정에서는 원래 충돌 기준과 입력·지도 초점을 유지한다. 결과가 불명확한 저장 요청은 기존 요청 재시도 경로를 유지한다.
- 새 공통 테스트 5개로 기간 단축·독립 수정·방문 삭제·불명확한 저장·명시적 재확인의 상태 보존을 검증한다.
- 검증: 모바일 공통 테스트 총 26개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 접근 종료 후 기기 데이터 정리 · AC17

- 여행 조회·장소 조회·검색·보기 상태 기록에서 접근 종료가 확인되면 계획·초안을 즉시 화면에서 제거하고 해당 여행의 로컬 기록을 정리한다.
- 초안 저장·확정 계획 캐시·저장 요청 기록·접근 종료 정리에 같은 잠금을 사용한다. 진행 중인 초안 저장을 취소하고 완료까지 기다린 뒤 삭제해, 늦은 쓰기가 데이터를 되살리지 못하게 한다.
- 접근 종료 시 처리 세대를 변경하고, 이전 조회·저장 응답은 화면이나 캐시를 복원하지 못하게 한다. 화면 이탈로 호출이 취소돼도 로컬 정리는 마친다.
- 권한 종료 뒤 남은 화면 콜백으로 방문 편집을 다시 열거나 초안을 저장하지 않도록 막는다.
- 새 ViewModel 회귀 테스트 3개로 비취소성 저장과 정리의 순서, 보기 상태 기록의 권한 종료, 늦은 조회 응답의 재노출 차단을 검증한다.
- 검증: 모바일 공통 테스트 총 29개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 최근 수정 표시와 직접 진입 · AC12·22

- 서버는 여행 변경 기록의 마지막 실제 시각을 일정 응답에 포함한다. 조회·보기 상태 기록만으로 수정 시각을 바꾸지 않으며 변경 기록이 없는 여행은 시각을 지어내지 않는다.
- 제목 아래 수정 시점은 화면 진입 또는 실제 수정 시각 변경 때 계산한다. 타이머·강조·미확인 개수 없이 표시하며, 사용자가 눌렀을 때 현재 일정 위에서 최근 변경을 연다.
- 최근 변경은 날짜별 그룹으로 묶고 그룹 안에서는 최신순으로 표시한다. 조회 중·실패·재시도·빈 상태를 같은 대화상자에서 처리하고, 권한 종료 시 열린 일정도 즉시 정리한다.
- 새 시각 필드는 기본값을 둬 이전 서버 응답과 기존 캐시를 읽을 수 있다. 캐시 왕복·상대 시각 경계·미래 서버 시각·서버 응답의 실제 수정 시각을 회귀 검증한다.
- 검증: 모바일 공통 테스트 총 33개·서버 전체 테스트 16개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과. 네 언어의 리소스 키·형식 인자도 대조했다.

## 여행 관리·알림 설정의 접근 종료 처리 · AC17

- 관리 화면의 회원 인증·여행 접근이 종료되면 이전 멤버·초대값·여행 정보·변경 내역을 즉시 비운다. 일반 통신 실패에서는 여행 정보 편집 내용을 유지한다.
- 최근 변경 확인 기록의 저장 실패도 권한 종료라면 같은 정리를 수행한다. 알림 설정에서 접근 종료를 발견한 경우 관리 화면에도 전달하고 이전 예약 정보를 숨긴다.
- 권한 종료·새 초대 확인은 진행 중인 관리 요청을 취소한다. 취소를 무시한 저장소가 늦은 성공이나 실패를 반환해도 현재 화면의 정보와 오류를 다시 바꾸지 않도록 확인한다.
- 회귀 테스트 6개로 멤버·초대·변경·여행 정보 정리, 통신 오류의 입력 보존, 늦은 성공·실패 차단, 알림 설정 정리를 확인한다.
- 검증: 모바일 공통 테스트 총 39개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 앱 패키징과 지속 검증 · P7

- 로컬 `:composeApp:assembleDebug`와 서버 전체 단위 테스트가 통과했다. Kotlin 컴파일 외에 Android APK 패키징도 확인했다.
- Android CI에서 공통 상태·복구 단위 테스트를 실행하고, 백엔드 CI에서 전체 서버 테스트를 실행하도록 연결했다. 실패 시에도 테스트 보고서를 보관한다.
- 백엔드 CI에 PostgreSQL 17 서비스를 추가했다. 새 통합 테스트는 실행별 별도 스키마에서 V39까지 기존 데이터를 만들고 V40 업그레이드 후 기록 보존, 현재 방문·삭제 상태 조인, 변경 확인 범위, 지연 순서 제약을 확인한다.
- PostgreSQL 테스트는 `TRAVEL_TEST_DATABASE_URL`이 명시된 환경에서만 실행한다. `TRAVEL_TEST_DATABASE_USER`, `TRAVEL_TEST_DATABASE_PASSWORD`로 전용 테스트 DB를 지정한다. 정리는 실행별 생성 스키마로 한정한다.
- 처음에는 로컬 PostgreSQL 부재로 통합 테스트 3개를 건너뛰었다. 후속 임시 DB 실행에서는 3개 모두 통과했다. 원격 CI에서 실행한 결과는 아직 없다.
- iOS 호스트 앱 확인을 위해 시작한 Xcode 패키지 준비는 8시간 이상 바이너리 아티팩트 대기에서 진행하지 않아 종료했다. Swift 호스트 전체 빌드 성공은 확인하지 못했다.

## 멤버 공통 여행 정보와 추천 출처 · AC01·14·15

- 여행 정보 메뉴를 모든 멤버에게 제공한다. 기본은 읽기 화면이며 소유자만 수정을 선택해 제목·도시·기간·시간대를 바꿀 수 있다. 서버의 소유자 수정 제한은 유지한다.
- 여행 정보에서 현재 여행의 날짜와 별도로 원래 추천 기간을 표시하고, 원래 도시 또는 기간 상세를 열 수 있다. 개인 연차 잔여량을 멤버에게 노출하지 않는다.

- iOS 패키지 준비의 SwiftPM 바이너리 다운로드 대기를 프로세스 샘플로 확인했다. 장시간 진행하지 않은 동일 작업을 종료했으며 중복 작업은 시작하지 않았다.

## 초대 웹 안내와 잘못된 링크 · AC10·22

- 초대 진입 페이지가 브라우저 언어에 맞춰 한국어·영어·일본어·중국어로 안내한다. 지원 언어가 없으면 영어를 사용하며 설치 후 같은 링크를 다시 여는 방법을 설명한다.

## 방문 편집의 공유 범위와 시각·순서 안내 · AC06·09

## 전체 날짜 위치 보기와 날짜 선택 후 추가 · AC05·07·18·19

- 날짜 선택 영역의 보조 버튼에서 전체 날짜 보기를 연다. 일차 숫자와 색을 함께 표시하고, 날짜 없음은 별도 표시한다. 전체 보기에서는 날짜 안팎의 연결선을 모두 생략한다.
- 날짜별 목록에는 좌표 없는 직접 입력 방문도 남긴다. 같은 장소를 여러 날 방문한 경우 방문별 항목을 유지하고 겹친 핀의 선택 목록에 날짜를 함께 표시한다.
- 방문 선택은 실제 배정 날짜·목록 행·핀으로 연결하며 편집창을 자동으로 열지 않는다. 전체 보기에서 장소를 추가할 때는 날짜 또는 날짜 없음을 직접 고른 뒤 검색으로 이동한다. 닫기만 하면 원래 보던 날짜를 유지한다.
- 회원 전용 `GET /api/v1/trips/{tripId}/places?language=ko`는 현재 접근을 확인한 뒤 여행 전체의 중복 없는 외부 장소 ID만 조회한다. 기존 외부 API 예산 제한을 유지하며, 일부 상세 실패는 가능한 위치·출처를 반환하고 실패 상태를 알린다. 예산 초과·네트워크 실패에서도 현재 가능한 위치와 전체 방문 목록은 유지한다.
- 전체 보기용 장소 정보는 일별 정보와 분리해 메모리에만 둔다. 닫힌 화면이나 접근이 종료된 화면을 늦은 응답으로 되살리지 않는다. 단순 메모·순서 변경에는 장소 정보를 다시 요청하지 않고, 첫 조회 완료 때만 지도를 한 번 맞춘다.
- 큰 글자에서는 목록을 먼저 표시하고 지도 표시를 선택할 수 있다. 날짜 라벨은 다크 테마에서도 본문색을 사용하고 색 표식을 따로 둔다. 새 문구는 네 언어에 반영했다.
- 모바일 회귀 테스트 7개(전체 보기 지도 1개·상태/권한/복귀 6개)를 추가해 공통 테스트 총 59개가 통과했다. 서버 단위 테스트 28개가 통과했으며, 이번 실행에서 환경 변수 미설정으로 PostgreSQL 통합 테스트 3개는 제외했다. DB 구조는 변경하지 않았다.
- Android·iOS Kotlin 컴파일, 변경 Kotlin 파일 스타일 검사, iOS 지도 브리지의 Swift 문법 검사가 통과했다. 실제 Google 지도 표시와 전체 Swift 호스트 빌드는 별도 검증 대상이다.

## 지도·목록 손잡이와 좁은 화면 날짜 선택 · AC07·19

- 지도와 목록 영역을 분리한 `TravelPlanPane`에서 목록 중심·함께 보기·지도 중심 상태를 제공한다. 중앙 손잡이의 세로 드래그로 한 단계씩 바꾸며, 같은 동작을 위·아래 버튼으로도 수행한다. 중앙 손잡이 탭은 목록과 함께 보기 사이를 전환한다.
- 실제 남은 영역에서 제어 버튼·상태 문구·범례·최소 목록 높이를 제외한 크기로 지도 높이를 제한한다. 두 영역을 함께 쓰기 어려운 높이나 큰 글자에서는 목록을 우선하며, 글자 크기 변경 시 측정 기준도 다시 잡는다. 날짜와 선택 방문은 기존 ViewModel 상태를 그대로 사용한다.
- 손잡이와 대체 버튼의 최소 조작 높이는 48dp이며 현재 보기 상태를 접근성 의미로 제공한다. 목록 본문·지도·방문 순서 손잡이에는 새 크기 조절 제스처를 연결하지 않는다.
- 360dp 미만의 화면 또는 큰 글자에서는 현재 날짜 버튼을 눌러 세로 날짜 선택 목록을 연다. 선택 날짜로 스크롤하고 현재 선택 의미를 제공하며, 날짜 없음과 전체 보기도 같은 목록에서 연다. 일반 화면의 기존 가로 날짜 선택은 유지한다.
- 새 문구를 네 언어에 반영했다. Android·iOS Kotlin 컴파일, 변경 Kotlin 파일 스타일 검사 및 네 언어 리소스 키 확인이 통과했다.
- 연결된 Android 기기는 없는 상태로 확인했다. 실제 드래그·지도 출처 영역·320dp/가로/큰 글자 레이아웃·스크린리더 검증과 전체 Swift 호스트 빌드는 아직 별도 검증이 필요하다.

## 오프라인 방문 메모 조회와 초안 분리 · AC16·17·18

- 온라인 편집 가능 여부와 방문 정보 조회 가능 여부를 분리했다. 연결이 끊겨 허용된 확정 계획을 표시하는 동안에도 방문 행에서 날짜·직접 입력 이름/위치·시각·공유 메모를 읽기 전용으로 연다. 긴 메모는 스크롤·선택해 확인할 수 있다.
- 조회 상태에는 방문 식별자만 두며 편집 초안이나 저장 요청을 새로 만들지 않는다. 기존 미저장 초안·결과 미확정 요청이 있으면 조회로 바꾸지 않는다. 닫기도 초안 저장소를 변경하지 않는다.
- 재조회에서 복구할 초안이 확인되면 초안을 우선하고, 방문 삭제나 접근 종료 시 조회 내용을 닫는다. 다른 날짜로 이동한 방문은 최신 방문 정보로 표시하되 기본 화면의 날짜를 강제로 바꾸지 않는다.
- 외부 길찾기는 편집 권한 상태와 분리한 공통 버튼으로 제공한다. HTTPS 지도 URL 열기가 실패하면 원인을 숨긴 채 무반응으로 끝내지 않고 재시도 안내를 표시한다. 자동 외부 요청은 추가하지 않았다.
- 새 문구를 네 언어에 반영했다. 회귀 테스트 4개로 오프라인 메모 유지·초안 쓰기 없음·기존 입력 보존·접근 종료/삭제 정리를 확인했고, 모바일 공통 테스트 총 63개가 통과했다. Android·iOS Kotlin 컴파일과 변경 Kotlin 파일 스타일 검사도 통과했다.
- 실제 기기에서 긴 메모 선택·스크린리더·외부 지도 앱/웹 전환을 확인한 결과는 아니다.

## 실제 동시 트랜잭션과 회원 스키마 누락 수정 · AC02·11·16·17

- 실제 PostgreSQL에서 Member·TravelPlan·TravelVisit·TravelPlanMembership의 Hibernate 스키마 검증과 JPA 저장소를 초기화하고, 운영 서비스의 작업을 JPA/JDBC 공통 트랜잭션 관리자로 실행하는 통합 테스트를 추가했다. 전체 애플리케이션 부팅을 검증하는 테스트는 아니다.
- 첫 트랜잭션의 커밋을 보류하고 두 번째 요청이 `pg_locks`에서 실제로 대기하는지 확인한 뒤 진행한다. 단순히 두 스레드를 시작한 상태를 동시 편집 성공으로 판단하지 않는다.
- 동시 생성 재시도·저장 명령 재전송·두 멤버의 추가·같은 메모 충돌·독립 필드 병합·같은 기준 순서 변경·삭제/수정·제외/저장과 강제 롤백을 검증한다. 방문뿐 아니라 순서·요청 중복 방지 기록·변경 기록도 확인한다.
- 이 실행에서 회원 엔티티의 `onboarding_completed` 열이 마이그레이션에 없어 새 DB의 실제 JPA 초기화가 실패하는 문제를 발견했다. V41에서 누락된 열을 기본 `false`로 추가하고, 수동으로 열을 보완한 DB의 기존 완료 값은 그대로 보존한다. 기존 적용 마이그레이션은 변경하지 않았다.
- 트랜잭션 테스트 9개와 온보딩 값 보존 회귀 테스트 1개를 추가했다. 임시 PostgreSQL 실행으로 서버 전체 41개(단위 28개·PostgreSQL 통합 13개)가 실패·건너뜀 없이 통과했다. 변경 테스트 파일 스타일 검사도 통과했다.
- 모든 검증은 도구가 생성한 임시 서버와 실행별 스키마에서 수행했다. 실행 종료 시 임시 서버가 정상 중지됐으며 운영 DB·기존 로컬 DB를 사용하지 않았다.

## 전체 날짜 장소 정보의 분할 조회와 이어받기 · AC18

- 전체 여행의 장소 수가 분당 조회 한도를 넘으면 기존 단일 요청은 조회 전체를 거절했다. 회원 전용 `POST /api/v1/trips/{tripId}/places/details`를 추가해 최대 30개씩 조회한다. 서버는 접근 권한과 모든 요청 ID의 여행 내 소속을 확인한 뒤 중복을 제거하며 기존 전체·회원별 예산 제한을 유지한다. 기존 GET 경로는 이전 앱을 위해 유지한다.
- 모바일은 이미 받은 같은 언어의 장소를 재사용하고 부족한 ID만 나누어 요청한다. 각 묶음의 성공 결과를 바로 합치므로 다음 요청이 한도·통신 오류로 실패해도 가능한 위치·목록·출처를 남긴다. 재시도는 부족한 장소부터 시작하며 자동 반복 요청은 하지 않는다.
- 일별 정보와 전체 보기의 언어를 구분해, 언어 변경 시 이전 언어의 공급자 정보를 새 결과로 취급하지 않는다. 공급자 응답은 기존처럼 메모리에만 유지한다.
- 조회 요청별 식별값으로 닫기·다시 열기 전의 늦은 응답이나 오류가 새 전체 보기를 바꾸지 못하게 했다.
- 모바일 회귀 테스트 4개와 서버 단위 테스트 4개를 추가했다. 모바일 테스트 총 67개·서버 단위 테스트 32개와 Android·iOS Kotlin 컴파일, 변경 Kotlin 파일 스타일 검사가 통과했다. 이번 서버 실행에서 PostgreSQL 통합 테스트 13개는 환경 변수 미설정으로 제외했으며 DB 구조 변경은 없다.

## 알림 취소·인계 경합과 공급자 실패 검증 · AC20

- 실제 PostgreSQL 트랜잭션 검증 7개를 추가했다. 취소·예약 변경·기기 로그아웃·멤버 제외·기간 변경이 먼저 확정되면 큐에서 이미 읽어 둔 이전 알림도 인계하지 않음을 확인한다. 각 경합에서 두 번째 요청의 실제 DB 잠금 대기를 확인한다.
- 인계가 먼저 확정된 뒤 취소한 경우 늦은 성공 기록이 취소 상태를 되살리지 않는다. 이전 예약 해제 요청은 새 예약을 취소하지 않으며 같은 예약 요청 재시도로 새 행을 만들지 않는다.
- 두 작업이 같은 예약을 확보해도 인계는 한 번만 시작한다. 알림 열기는 본인의 현재 예약과 접근 권한을 다시 확인하며, 같은 여행의 다른 멤버라도 다른 사람의 개인 알림 ID로 열지 못한다.
- 발송 작업 단위 테스트 7개로 설정 없음·인증 준비 실패·큐에서 읽은 후 취소·공급자 수락·거절·결과 불명확·스레드 중단을 검증한다. 결과 불명확 또는 중단 후 같은 작업에서 자동 재전송하지 않음을 확인한다.
- 임시 PostgreSQL 실행에서 서버 전체 59개(단위 39개·PostgreSQL 통합 20개)가 실패·건너뜀 없이 통과했다. 변경 Kotlin 파일 스타일 검사도 통과했다. 테스트 종료 시 임시 서버는 정상 중지됐다.
- 실제 공급자 호출은 모형으로 대체했다. 실제 푸시 수락·기기 표시·OS 권한·종료 상태 수신·계정 전환의 플랫폼 동작은 여전히 별도 기기 검증 대상이다.

## iOS 전체 호스트 앱 빌드 확인 · P7

- 기존 패키지 준비 대기는 SwiftPM 바이너리 다운로드 단계에서 재현됐다. 공개 SDK의 다운로드 주소는 정상 응답했지만 해당 Xcode 프로세스에는 네트워크 연결이나 CPU 작업이 없었다. 프로세스 기록을 확인한 뒤 이 작업만 종료했다.
- 로컬 Xcode 도움말이 제공하는 `-packageAuthorizationProvider netrc` 옵션을 빌드 명령에 적용하자 고정된 패키지 버전의 준비가 정상 완료됐다. 전역 키체인이나 적용 패키지 버전은 변경하지 않았다. 관련 증상은 테스트 가이드의 도구 이슈 링크에 남겼다.
- `iosApp-Debug`, Debug, arm64, iOS Simulator, 코드 서명 비활성화 구성으로 실제 Xcode 앱 빌드가 통과했다. TravelMapBridge·TravelReminderPushDelegate·iOSApp의 Swift 컴파일과 Kotlin 프레임워크 연결을 확인했고, `Oguri.app`의 arm64 실행 파일이 생성됐다. Kotlin 프레임워크는 프로젝트 설정대로 정적 연결된다.
- 재현 명령을 `scripts/verify_ios_simulator.sh`에 추가했다. 명시한 Xcode 선택을 존중하며 기본값이 Command Line Tools일 때 설치된 전체 Xcode를 선택한다. 스크립트 문법 검사와 실제 스크립트를 통한 전체 앱 빌드도 통과했다.
- 프로젝트·Downloads·완성 앱 번들에서 iOS용 Firebase plist는 찾지 못했다. 준비된 파일의 로컬 경로를 요청한 상태다. 현재 Debug 초기화 코드는 해당 파일이 없으면 실행을 중단하므로 실제 앱 실행·지도 표시·푸시 전달을 확인한 결과로 기록하지 않는다. 전체 Swift 호스트 컴파일 미확인 항목은 이번 결과로 해소됐고, 기기 동작 검증은 남아 있다.

## 홈 이어보기의 재진입 갱신과 안정적인 선정 · AC13·17

- 홈의 이어보기 조회를 최초 구성 시 한 번에서 화면이 다시 활성화될 때마다 실행하는 방식으로 바꿨다. 화면을 떠나면 진행 중인 조회는 취소하며 홈에서 주기적으로 재조회하지 않는다.
- 조회 요청과 접근 상태 세대를 확인하고 취소 상태도 검사해, 늦은 이전 응답이 최신 카드나 접근 종료 상태를 덮어쓰지 못하게 했다. 대상 없음·인증 실패는 카드만 숨기고 추천 홈 전체를 오류 화면으로 바꾸지 않는다.
- 모바일 회귀 테스트 4개로 이전/최신 응답 경합·화면 이탈 취소·접근 종료 뒤 복원 차단·빈 결과와 인증 실패를 확인한다.
- 실제 PostgreSQL 검증 4개로 가까운 예정 여행 기본 선택·내 최근 열람 우선·친구 수정의 영향 없음·진행 중 여행 우선·지난 여행 목록 보존·제외 멤버의 이어보기 제거를 확인했다. 서버 선정 알고리즘 자체는 기존 명세와 일치해 변경하지 않았다.
- 모바일 테스트 총 71개, 서버 전체 63개(단위 39개·PostgreSQL 통합 24개)가 실패·건너뜀 없이 통과했다. Android·iOS Kotlin 컴파일과 변경 Kotlin 파일 스타일 검사도 통과했다. 임시 DB는 실행 종료 시 정상 중지됐다.

## iOS Firebase 로컬 구성 연결과 앱 실행 · P7

- 사용자가 Downloads에 제공한 Debug·Release plist를 각각의 앱 번들 식별자와 비교한 뒤 `iosApp/iosApp`의 로컬 리소스에 복사했다. 두 파일은 기존 Git 제외 규칙을 유지하며 설정 값은 출력하거나 커밋하지 않았다.
- 전체 iOS 시뮬레이터 빌드가 다시 통과했다. 생성된 앱 번들에 Debug plist가 포함됐고 Firebase와 앱의 번들 식별자가 일치함을 확인했다.
- iPhone 17 Pro·iOS 26.2 시뮬레이터에 실제 앱을 설치·실행해 애플/카카오 로그인과 비회원 둘러보기 버튼이 있는 로그인 화면을 확인했다. 기존 Firebase 파일 누락으로 인한 시작 중단은 해소됐다.
- 비회원 둘러보기로 홈 진입까지 확인했으나, 뒤이은 화면 조작에서 테스트 광고가 표시되어 이번 실행에서는 비회원 여행 진입 차단의 화면 검증까지 완료하지 않았다. 기존 자동 테스트 결과와 구분한다. 회원 로그인·지도·실제 푸시 수신·두 계정 협업 검증도 남아 있다.

## 여행 지표의 확정 사실과 기초 집계 · 14.2·P7

- 신규 여행 생성·명시적 첫 참여의 관찰 시작과 서버 확정 편집을 V42의 별도 사실 테이블에 기록한다. 임의 속성이나 사용자 작성 문자열을 받지 않고 앱 소유 DB에만 저장한다. 외부 분석 전송은 추가하지 않았다.
- 여행·요청 기록과 같은 실제 트랜잭션에서 저장하므로 재시도·동시 재전송·실패·충돌·롤백이 성공 수를 부풀리지 않는다. 재참여도 새 관찰 시작으로 바꾸지 않는다.
- 최초 출발까지 남은 날짜와 종료 기준을 보존한다. 기간 변경·나가기·제외·삭제·탈퇴로 관찰 분모를 빼지 않으며, 삭제된 여행/계정의 참조는 비운다. 수집 이전 여행의 시작은 `EXISTING`·미상으로 구분하고 소급 생성하지 않는다.
- 날짜에 배정된 방문이 하나 이상인 저장을 활성화 사실로 남긴다. 시각·메모·재정렬은 조건이 아니다. 다른 멤버의 실제 참여 이후 편집을 별도로 기록하며 링크 발급만으로 협업으로 세지 않는다.
- 읽기 전용 기초 집계 `scripts/report_travel_usage.sql`과 수집 정의·실행 방법·미구현 범위를 `TRAVEL_PLANNER_METRICS.md`에 추가했다. 도시가 미정인 기간 추천도 추천 출처로 구분한다. 관찰 완료와 진행 중, 임박·여행 중·과거·시작 미상 집단을 구분한다.
- 실제 PostgreSQL 회귀 테스트 7개를 추가하고 기존 동시 생성·동시 추가·재전송 검증에도 지표 수를 확인했다. 집계 SQL 자체도 실행해 추천 출처·활성화·관찰 완료 구분을 확인했다. 서버 전체 70개(단위 39개·PostgreSQL 31개)가 실패·건너뜀 없이 통과했고 임시 서버는 정상 중지됐다. 변경 Kotlin 파일의 엄격한 스타일 검사도 통과했다.
- 이 단위는 세션별 재사용·추천 노출/클릭·실패·알림 해제·90일 다음 여행 재사용률의 완료가 아니다. 목적 있는 행동/세션 수집과 실제 사용자 과업·기기 검증을 계속해야 한다.

## 세션별 준비 기간 재사용 수집과 집계 · 14.2·P7

- 생성·명시적 참여·확정 편집에 선택적인 무작위 세션 식별자를 연결했다. V43으로 기존 시작/편집의 세션 미상은 그대로 두고, 이후 행동이나 재시도로 첫 세션을 바꾸지 않는다. 이전 앱의 요청 형식은 계속 허용한다.
- 새 모바일 세션은 프로세스 시작·30분 행동 공백·계정 버전 변경에 구분된다. 단조 시계를 사용하며 자동 조회는 세션을 연장하지 않는다. 늦은 이전 계정의 요청도 새 계정 세션을 되돌리거나 나누지 않는다. 자동 인증 갱신은 같은 계정 버전을 유지한다.
- 회원 전용 행동 API는 현재 계획 접근을 다시 확인한다. 활성화된 화면의 실제 표시, 사용자의 날짜 선택·전체 날짜 보기·핀 선택·변경 표시·성공한 외부 길찾기 열기를 구분한다. 자동 날짜 복원·알림 날짜 이동·5초 조회·앱 실행·푸시 클릭 자체는 목적 행동이 아니다. 서버 시각으로 종류별 최초 행동만 기록한다.
- 성공한 같은 세션·여행·행동은 모바일과 서버에서 중복을 막는다. 모바일 수집 실패는 여행 상태·초안·접근 처리를 변경하지 않으며 오프라인 수집 큐나 자동 재시도를 추가하지 않았다. 세션 식별자 이외의 새 자유 입력 속성은 없다.
- 읽기 전용 `scripts/report_travel_preparation_reuse.sql`은 시작 당시 출발까지 8일 이상이고 관찰 7일을 마친 집단에서 시작 후 24시간부터 7일 이내의 다른 세션 목적 행동/저장만 집계한다. 표시만 된 재방문은 별도 열이다. 시작 세션 미상·관찰 중·계정 참조 없는 관찰을 구분하며 사용자–여행 수와 출처별/앱 전체 고유 사용자 수를 따로 반환한다.
- 모바일 테스트 4개로 유휴 경계·계정/프로세스 변경·동시 호출·오래된 계정 거절·온라인 현재 화면 조건·수집 실패의 편집 상태 보존을 확인했다. 실제 DB 테스트 4개로 행동 중복/권한·재전송 세션 보존·24시간/7일 경계/같은 세션/표시와 편집 구분·구버전 세션 미상 보존을 확인했다. API 테스트 2개로 유효한 유형/세션 전달과 미상 유형·세션 누락/형식 오류 거절을 확인했다.
- Android 공통 테스트 75개, 서버 전체 76개(단위 41개·PostgreSQL 35개)가 실패·건너뜀 없이 통과했고 임시 DB는 정상 중지됐다. Android·iOS Kotlin 컴파일과 변경 Kotlin 파일 스타일 검사가 통과했다. 실제 기기 이벤트 전달과 실제 리텐션 효과를 확인한 결과는 아니다.
- 추천 진입 노출/클릭·변경 확인 후 후속 행동·실패/알림 해제·90일 다음 여행 집계, 실제 사용자 과업과 기기 검증은 계속 남아 있다.
