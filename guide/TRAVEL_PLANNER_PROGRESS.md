# 여행 플래너 구현 진행 기록

기준: 2026-11-13, `9eef5c4` 이후 이어서 작업. 이 기록은 이번 변경의 범위와 검증 결과이며, 공개 MVP 전체의 완료를 의미하지 않는다.

## 이번에 연결한 흐름 · P6

- 여행 화면의 `더보기`에서 멤버·여행 관리 화면을 열고, 개인 구역의 `내 알림`을 선택한다.
- 현재 본인 예약을 조회하고 날짜·현지 시각·수신 시간대를 입력해 출발 전 1회 알림을 예약하거나 해제한다. 기본 상태는 꺼짐이며, 예약을 직접 누를 때만 OS 권한을 요청한다.
- 미래 시각과 여행 시간대 기준 출발일 시작 전인지 검사한다. 존재하지 않는 서머타임 시각은 입력 단계에서 막는다. 서버가 시간대 중복 시각과 여행 구조·권한을 최종 검증한다.
- 예약 상태·권한 거절·통신 실패를 표시한다. 기간 변경으로 취소된 예약은 설정을 다시 조회하면 꺼짐으로 표시된다. 자동 재예약은 하지 않는다.
- 앱의 계정 세션·푸시 토큰 변경과 포그라운드 복귀에 기기 연결을 동기화한다. 로그아웃·계정 변경 시 이전 연결을 해제하며, 해제 요청 실패 기록은 다음 동기화에서 재시도한다.
- 알림을 누르면 서버에서 예약의 최신 상태와 현재 계정의 접근 권한을 확인한 뒤 여행을 연다. 로그인 중에는 진입 의도를 유지하고, 통신 실패는 재시도할 수 있다. 유효하지 않은 알림은 여행을 열지 않는다.
- 인증 갱신 재시도에서 같은 예약 요청 ID를 유지하고, 이전 계정의 푸시 토큰을 정리한 뒤 새 토큰을 얻도록 순서를 정리했다.
- 새 문구는 영어·한국어·일본어·중국어에 반영했다.

## 실행 검증

- `:composeApp:compileDebugKotlinAndroid`: 로컬 Firebase 설정을 포함해 통과.
- `:composeApp:compileKotlinIosSimulatorArm64`: 통과. Swift 호스트 앱 전체 빌드와 실제 APNs 전달을 확인한 결과는 아니다.
- `:composeApp:testDebugUnitTest`: 공통 테스트 12개 통과. 새 알림 테스트 5개는 수신 시간대 변환, 여행 시간대의 출발일 경계, 과거·현재 시각, 잘못된 입력, 서머타임 누락 시각을 검증한다.
- 변경한 Kotlin 파일만 대상으로 스타일 포맷·검사를 수행한다. 저장소 전체 검사는 생성된 네트워크 설정 소스와 관련한 기존 Gradle 태스크 의존성 문제를 별도로 해결해야 한다.
- 로컬 Firebase 파일은 각 `composeApp/src/debug`, `composeApp/src/release` 폴더에서 `google-services.json`이라는 이름을 사용한다. 두 파일 모두 Git 제외 대상이다.

## 최근 변경 상세 보완 · AC12

- V40에서 방문 식별자만 변경 기록에 추가한다. 삭제·이동 뒤에도 같은 방문을 구별하며, 장소 이름이나 메모 본문을 변경 이력으로 복제하지 않는다.
- 최근 변경 조회 시 현재 방문과 조인해 변경 시각, 현재 직접 입력 이름, 현재 배정 날짜를 응답한다. Google 장소 상세는 이력에 저장하지 않는다.
- 변경 항목은 최신순으로 표시하고, 이동한 방문은 현재 날짜로 연결한다. 삭제된 방문은 현재 삭제 상태를 안내하며 오래된 날짜로 이동시키지 않는다. 기간 단축 뒤 날짜 없음으로 옮겨진 방문도 이동할 수 있다.
- 현재 여행 기간·시간대를 함께 내려 주어 관리 화면을 연 뒤 기간이 바뀌어도 이전 날짜 범위를 사용하지 않는다. 이전 서버의 응답은 기존 일차 기반으로 호환한다.
- 모바일 테스트 5개로 이동·미배정·삭제·기간 단축·이전 응답의 이동 대상을 검증한다. 서버 테스트 3개로 추가·이동·삭제의 방문 식별자 기록을 검증한다.
- 검증: 모바일 공통 테스트 총 17개·여행 변경 서버 테스트 3개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사가 통과했다.
- PostgreSQL에서 V40 적용과 실제 최근 변경 SQL 조회는 추가 확인이 필요하다.
- 초기 전체 서버 검사에서 `CalendarServiceTest`의 2026년 6월 고정 날짜 사례가 과거 날짜 필터로 실패했다. 후속 수정에서 테스트 연도를 현재 연도의 다음 해로 바꾸어 테스트 목적을 유지했고, 전체 서버 테스트 15개가 통과했다.


## 회원 전용 여행 일정 정책

- 사용자 정책 변경에 따라 비회원에게는 여행 목록·생성·편집·관리 대신 로그인 안내만 표시한다. 게이트 뒤에서만 해당 ViewModel과 입력 화면을 만든다.
- 로그인·가입 후에는 원래 진입 경로와 추천 도시·기간으로 복귀한다. 로그인 취소 시 일정 입력을 제공하지 않는다.
- 도시 검색·도시 시간대 API도 인증 대상에 추가하고 실제 회원 존재를 확인한다. 기존 여행 조회·쓰기·초대 참여의 회원 검증은 유지한다.
- 제한된 초대 안내, 기존 추천 탐색, 로그아웃 후 기기 연결 해제 API는 기존 목적대로 사용할 수 있다.
- 검증: 모바일 공통 테스트 17개, 여행 서버 테스트 7개(인증 정책·탈퇴 회원 차단 포함), Android·iOS Kotlin 컴파일 및 변경 파일 스타일 검사 통과.


## 여행 생성 재실행 복구 · AC16

- 회원의 이전 생성 요청을 로컬 저장소에서 확인하기 전에는 새 여행 생성을 막는다. 복구 읽기가 실패하면 새 요청으로 진행하지 않고 복구 확인을 재시도한다.
- 응답을 확인하지 못한 생성 요청이 남아 있으면 도시·여행 기간·시간대·제목·추천 출처를 복원한다. 사용자는 같은 요청 ID로 재시도한다.
- 복구 대기 중 생성, 복구 저장소 읽기 실패, 통신 결과 불명확 후 재시도, 생성 중복 탭을 ViewModel 테스트 4개로 검증한다.
- 검증: 모바일 공통 테스트 총 21개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 공동 편집 중 편집 상태 보호 · AC11·14·16

- 다른 멤버가 기간·시간대를 바꾸면 열린 방문 초안은 그대로 보존하고 최신 일정 확인을 요구한다. 사용자가 확인한 뒤 새 구조 버전을 적용하며 범위 밖 일차는 날짜 없음으로 옮긴다.
- 기간 단축으로 존재하지 않게 된 일차도 편집창·최근 변경에서 안전하게 표시한다. 유효하지 않은 일차로 날짜 계산을 하거나 날짜 문구의 필수 인자를 누락하지 않는다.
- 다른 멤버가 편집 중인 방문을 삭제하면 선택·지도 초점을 정리하고 삭제 상태를 표시하되, 사용자가 입력한 내용은 버리지 않는다.
- 독립적인 방문 필드 수정에서는 원래 충돌 기준과 입력·지도 초점을 유지한다. 결과가 불명확한 저장 요청은 기존 요청 재시도 경로를 유지한다.
- 새 공통 테스트 5개로 기간 단축·독립 수정·방문 삭제·불명확한 저장·명시적 재확인의 상태 보존을 검증한다.
- 검증: 모바일 공통 테스트 총 26개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 접근 종료 후 기기 데이터 정리 · AC17

- 여행 조회·장소 조회·검색·보기 상태 기록에서 접근 종료가 확인되면 계획·초안을 즉시 화면에서 제거하고 해당 여행의 로컬 기록을 정리한다.
- 초안 저장·확정 계획 캐시·저장 요청 기록·접근 종료 정리에 같은 잠금을 사용한다. 진행 중인 초안 저장을 취소하고 완료까지 기다린 뒤 삭제해, 늦은 쓰기가 데이터를 되살리지 못하게 한다.
- 접근 종료 시 처리 세대를 변경하고, 이전 조회·저장 응답은 화면이나 캐시를 복원하지 못하게 한다. 화면 이탈로 호출이 취소돼도 로컬 정리는 마친다.
- 권한 종료 뒤 남은 화면 콜백으로 방문 편집을 다시 열거나 초안을 저장하지 않도록 막는다.
- 새 ViewModel 회귀 테스트 3개로 비취소성 저장과 정리의 순서, 보기 상태 기록의 권한 종료, 늦은 조회 응답의 재노출 차단을 검증한다.
- 검증: 모바일 공통 테스트 총 29개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 최근 수정 표시와 직접 진입 · AC12·22

- 서버는 여행 변경 기록의 마지막 실제 시각을 일정 응답에 포함한다. 조회·보기 상태 기록만으로 수정 시각을 바꾸지 않으며 변경 기록이 없는 여행은 시각을 지어내지 않는다.
- 제목 아래 수정 시점은 화면 진입 또는 실제 수정 시각 변경 때 계산한다. 타이머·강조·미확인 개수 없이 표시하며, 사용자가 눌렀을 때 현재 일정 위에서 최근 변경을 연다.
- 최근 변경은 날짜별 그룹으로 묶고 그룹 안에서는 최신순으로 표시한다. 조회 중·실패·재시도·빈 상태를 같은 대화상자에서 처리하고, 권한 종료 시 열린 일정도 즉시 정리한다.
- 새 시각 필드는 기본값을 둬 이전 서버 응답과 기존 캐시를 읽을 수 있다. 캐시 왕복·상대 시각 경계·미래 서버 시각·서버 응답의 실제 수정 시각을 회귀 검증한다.
- 검증: 모바일 공통 테스트 총 33개·서버 전체 테스트 16개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과. 네 언어의 리소스 키·형식 인자도 대조했다.

## 여행 관리·알림 설정의 접근 종료 처리 · AC17

- 관리 화면의 회원 인증·여행 접근이 종료되면 이전 멤버·초대값·여행 정보·변경 내역을 즉시 비운다. 일반 통신 실패에서는 여행 정보 편집 내용을 유지한다.
- 최근 변경 확인 기록의 저장 실패도 권한 종료라면 같은 정리를 수행한다. 알림 설정에서 접근 종료를 발견한 경우 관리 화면에도 전달하고 이전 예약 정보를 숨긴다.
- 권한 종료·새 초대 확인은 진행 중인 관리 요청을 취소한다. 취소를 무시한 저장소가 늦은 성공이나 실패를 반환해도 현재 화면의 정보와 오류를 다시 바꾸지 않도록 확인한다.
- 회귀 테스트 6개로 멤버·초대·변경·여행 정보 정리, 통신 오류의 입력 보존, 늦은 성공·실패 차단, 알림 설정 정리를 확인한다.
- 검증: 모바일 공통 테스트 총 39개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사 통과.

## 앱 패키징과 지속 검증 · P7

- 로컬 `:composeApp:assembleDebug`와 서버 전체 단위 테스트가 통과했다. Kotlin 컴파일 외에 Android APK 패키징도 확인했다.
- Android CI에서 공통 상태·복구 단위 테스트를 실행하고, 백엔드 CI에서 전체 서버 테스트를 실행하도록 연결했다. 실패 시에도 테스트 보고서를 보관한다.
- 백엔드 CI에 PostgreSQL 17 서비스를 추가했다. 새 통합 테스트는 실행별 별도 스키마에서 V39까지 기존 데이터를 만들고 V40 업그레이드 후 기록 보존, 현재 방문·삭제 상태 조인, 변경 확인 범위, 지연 순서 제약을 확인한다.
- PostgreSQL 테스트는 `TRAVEL_TEST_DATABASE_URL`이 명시된 환경에서만 실행한다. `TRAVEL_TEST_DATABASE_USER`, `TRAVEL_TEST_DATABASE_PASSWORD`로 전용 테스트 DB를 지정한다. 정리는 실행별 생성 스키마로 한정한다.
- 현재 로컬에는 PostgreSQL 서버가 없어 통합 테스트 3개는 컴파일·발견만 확인하고 건너뛴다. CI 서비스에서 실제 실행한 결과는 아직 없다. 앞서 남긴 V40 실제 적용 미검증 상태를 완료로 바꾸지 않는다.
- iOS 호스트 앱 확인을 위해 Xcode 패키지 준비를 시작했다. 현재 `xcodebuild -list`의 패키지 준비 작업이 실행 중이며, Swift 호스트 전체 빌드 성공을 확인한 상태는 아니다.

## 멤버 공통 여행 정보와 추천 출처 · AC01·14·15

- 여행 정보 메뉴를 모든 멤버에게 제공한다. 기본은 읽기 화면이며 소유자만 수정을 선택해 제목·도시·기간·시간대를 바꿀 수 있다. 서버의 소유자 수정 제한은 유지한다.
- 여행 정보에서 현재 여행의 날짜와 별도로 원래 추천 기간을 표시하고, 원래 도시 또는 기간 상세를 열 수 있다. 개인 연차 잔여량을 멤버에게 노출하지 않는다.
- 추천 출처 복귀는 저장된 출처의 날짜·도시 ID만 사용한다. 실제 여행 날짜로 출처를 바꾸거나, 불완전한 출처에서 임의의 추천을 열지 않는다.
- 출처 경로 회귀 테스트 4개로 도시·기간·날짜 없는 도시·불완전 출처의 동작을 확인했다. 모바일 공통 테스트 총 43개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사가 통과했다.
- iOS 패키지 준비는 동일한 Xcode 프로세스에서 계속 실행 중이다. 프로세스 샘플에서 SwiftPM 바이너리 아티팩트 다운로드 대기임을 확인했으며, 작업을 중복 시작하지 않았다.

## 서버 공동 편집 규칙 검증 · AC05·06·11·14·16

- 날짜 이동 뒤 이전 화면의 독립 메모 수정을 병합하면 최근 변경 기록이 이전 일차를 가리키던 결함을 회귀 테스트로 재현했다. 병합이 끝난 방문의 실제 일차를 기록하도록 수정했다.
- 도메인 테스트 7개로 독립 필드 병합, 같은 메모 충돌, 날짜 이동과 독립 수정, 기간 단축의 장소·순서 보존, 오래된 영향 확인 거절, 순서 충돌·삭제 후 수정 거절, 다른 수정 이후 안전한 되돌리기를 검증한다.
- 검증: 서버 단위 테스트 총 24개와 변경 파일 스타일 검사 통과. PostgreSQL 통합 테스트 3개는 전용 DB가 없어 계속 건너뛴 상태다.
