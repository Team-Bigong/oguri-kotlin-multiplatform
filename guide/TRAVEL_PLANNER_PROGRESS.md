# 여행 플래너 구현 진행 기록

기준: 2026-11-13, `9eef5c4` 이후 이어서 작업. 이 기록은 이번 변경의 범위와 검증 결과이며, 공개 MVP 전체의 완료를 의미하지 않는다.

## 이번에 연결한 흐름 · P6

- 여행 화면의 `더보기`에서 멤버·여행 관리 화면을 열고, 개인 구역의 `내 알림`을 선택한다.
- 현재 본인 예약을 조회하고 날짜·현지 시각·수신 시간대를 입력해 출발 전 1회 알림을 예약하거나 해제한다. 기본 상태는 꺼짐이며, 예약을 직접 누를 때만 OS 권한을 요청한다.
- 미래 시각과 여행 시간대 기준 출발일 시작 전인지 검사한다. 존재하지 않는 서머타임 시각은 입력 단계에서 막는다. 서버가 시간대 중복 시각과 여행 구조·권한을 최종 검증한다.
- 예약 상태·권한 거절·통신 실패를 표시한다. 기간 변경으로 취소된 예약은 설정을 다시 조회하면 꺼짐으로 표시된다. 자동 재예약은 하지 않는다.
- 앱의 계정 세션·푸시 토큰 변경과 포그라운드 복귀에 기기 연결을 동기화한다. 로그아웃·계정 변경 시 이전 연결을 해제하며, 해제 요청 실패 기록은 다음 동기화에서 재시도한다.
- 알림을 누르면 서버에서 예약의 최신 상태와 현재 계정의 접근 권한을 확인한 뒤 여행을 연다. 로그인 중에는 진입 의도를 유지하고, 통신 실패는 재시도할 수 있다. 유효하지 않은 알림은 여행을 열지 않는다.
- 인증 갱신 재시도에서 같은 예약 요청 ID를 유지하고, 이전 계정의 푸시 토큰을 정리한 뒤 새 토큰을 얻도록 순서를 정리했다.
- 새 문구는 영어·한국어·일본어·중국어에 반영했다.

## 실행 검증

- `:composeApp:compileDebugKotlinAndroid`: 로컬 Firebase 설정을 포함해 통과.
- `:composeApp:compileKotlinIosSimulatorArm64`: 통과. Swift 호스트 앱 전체 빌드와 실제 APNs 전달을 확인한 결과는 아니다.
- `:composeApp:testDebugUnitTest`: 공통 테스트 12개 통과. 새 알림 테스트 5개는 수신 시간대 변환, 여행 시간대의 출발일 경계, 과거·현재 시각, 잘못된 입력, 서머타임 누락 시각을 검증한다.
- 변경한 Kotlin 파일만 대상으로 스타일 포맷·검사를 수행한다. 저장소 전체 검사는 생성된 네트워크 설정 소스와 관련한 기존 Gradle 태스크 의존성 문제를 별도로 해결해야 한다.
- 로컬 Firebase 파일은 각 `composeApp/src/debug`, `composeApp/src/release` 폴더에서 `google-services.json`이라는 이름을 사용한다. 두 파일 모두 Git 제외 대상이다.

## 다음에 확인할 사항

- Android·iOS 실제 기기에서 권한 허용·거절, 예약·해제·기간 변경, 로그아웃·계정 전환, 앱 종료 상태 수신·알림 진입을 검증한다.
- 서버 발송 자격 증명, Firebase 프로젝트·Android 앱 ID, APNs 키·서명·환경 설정을 실제 전달과 함께 확인한다. Firebase 설정 파일 추가만으로 발송까지 검증된 것으로 보지 않는다.
- 두 계정·두 기기의 공동 편집과 초대 링크를 포함해 P7의 AC01–AC22를 검증한다. 지도·링크·접근성·다국어 화면의 실제 기기 검증도 남아 있다.

## 최근 변경 상세 보완 · AC12

- V40에서 방문 식별자만 변경 기록에 추가한다. 삭제·이동 뒤에도 같은 방문을 구별하며, 장소 이름이나 메모 본문을 변경 이력으로 복제하지 않는다.
- 최근 변경 조회 시 현재 방문과 조인해 변경 시각, 현재 직접 입력 이름, 현재 배정 날짜를 응답한다. Google 장소 상세는 이력에 저장하지 않는다.
- 변경 항목은 최신순으로 표시하고, 이동한 방문은 현재 날짜로 연결한다. 삭제된 방문은 현재 삭제 상태를 안내하며 오래된 날짜로 이동시키지 않는다. 기간 단축 뒤 날짜 없음으로 옮겨진 방문도 이동할 수 있다.
- 현재 여행 기간·시간대를 함께 내려 주어 관리 화면을 연 뒤 기간이 바뀌어도 이전 날짜 범위를 사용하지 않는다. 이전 서버의 응답은 기존 일차 기반으로 호환한다.
- 모바일 테스트 5개로 이동·미배정·삭제·기간 단축·이전 응답의 이동 대상을 검증한다. 서버 테스트 3개로 추가·이동·삭제의 방문 식별자 기록을 검증한다.
- 검증: 모바일 공통 테스트 총 17개·여행 변경 서버 테스트 3개, Android·iOS Kotlin 컴파일과 변경 파일 스타일 검사가 통과했다.
- PostgreSQL에서 V40 적용과 실제 최근 변경 SQL 조회는 추가 확인이 필요하다.
- 전체 서버 테스트에서 기존 `CalendarServiceTest`의 2026년 6월 고정 날짜 사례가 실패한다. 현재 시각 기준 이미 지난 기간이므로 빈 추천을 반환한다. 여행 변경 테스트는 별도로 통과했다.


## 회원 전용 여행 일정 정책

- 사용자 정책 변경에 따라 비회원에게는 여행 목록·생성·편집·관리 대신 로그인 안내만 표시한다. 게이트 뒤에서만 해당 ViewModel과 입력 화면을 만든다.
- 로그인·가입 후에는 원래 진입 경로와 추천 도시·기간으로 복귀한다. 로그인 취소 시 일정 입력을 제공하지 않는다.
- 도시 검색·도시 시간대 API도 인증 대상에 추가하고 실제 회원 존재를 확인한다. 기존 여행 조회·쓰기·초대 참여의 회원 검증은 유지한다.
- 제한된 초대 안내, 기존 추천 탐색, 로그아웃 후 기기 연결 해제 API는 기존 목적대로 사용할 수 있다.
- 검증: 모바일 공통 테스트 17개, 여행 서버 테스트 7개(인증 정책·탈퇴 회원 차단 포함), Android·iOS Kotlin 컴파일 및 변경 파일 스타일 검사 통과.
